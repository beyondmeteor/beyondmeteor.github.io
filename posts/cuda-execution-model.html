CUDA Execution Model: Kernel, Grid, Block, Warp & SM

One kernel definition, many logical threads: how the GPU partitions work and maps it to execution hardware.

1. Start with vector addition

#define N 2048
__global__ void VecAdd(const float* A, const float* B, float* C) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < N) C[i] = A[i] + B[i];
}
VecAdd<<<(N + 1023) / 1024, 1024>>>(d_A, d_B, d_C);

The launch syntax is kernel<<<gridDim, blockDim>>>(args). Here integer division gives (2048+1023)/1024 = 2, so the grid contains two blocks, each with 1024 threads.

2. How each thread gets unique work

For block 1, thread 0: i = 1 * 1024 + 0 = 1024. That instance computes C[1024]. Each thread runs the same code but sees its own built-in indices.

3. Logical versus physical hierarchy

A thread block is scheduled onto one SM for its lifetime. A single SM can host multiple blocks if registers, shared memory, and other resource limits allow. On NVIDIA CUDA GPUs, a warp contains 32 threads; warp schedulers issue instructions over time, so 2048 logical threads do not imply 2048 physical execution cores.

4. Why round up?

int threadsPerBlock = 256;
int blocks = (N + threadsPerBlock - 1) / threadsPerBlock;
VecAdd<<<blocks, threadsPerBlock>>>(d_A, d_B, d_C);

For N=2050 and 1024 threads/block, the grid needs three blocks; the bounds check skips 1022 extra threads. Block size is a tuning parameter, not something to always maximize.

Key distinction: Block is a logical scheduling unit, SM is hardware, warp is the execution grouping. Triton's program instance roughly corresponds to one CUDA thread block, but Triton expresses per-tile operations at a higher abstraction level.

CUDA 执行模型：Kernel、Grid、Block、Warp 与 SM

只写一个 Kernel，GPU 却能启动数千逻辑线程；重点理解工作划分与硬件执行的关系。

1. 从向量加法开始

#define N 2048
__global__ void VecAdd(const float* A, const float* B, float* C) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < N) C[i] = A[i] + B[i];
}
VecAdd<<<(N + 1023) / 1024, 1024>>>(d_A, d_B, d_C);

kernel<<<gridDim, blockDim>>>(args) 中第一个参数是 Grid 的 Block 数，第二个是每块线程数。整数计算 (2048+1023)/1024 = 2，所以启动 2 个 Block × 1024 Threads。

2. 每个线程如何处理不同数据？

i = 0…1023

例如 Block 1 的 Thread 0 得到 i = 1 * 1024 + 0 = 1024，负责 C[1024]。线程运行同一段代码，但各自的内置索引不同。

Block 被调度到某个 SM，并在生命周期中由该 SM 执行。资源允许时，一个 SM 可驻留多个 Block。NVIDIA CUDA 的 Warp 通常是 32 个线程；Warp 调度器分时发射指令，所以 2048 个逻辑线程不等于 2048 个物理核心。

4. 为什么写向上取整？

int threadsPerBlock = 256;
int blocks = (N + threadsPerBlock - 1) / threadsPerBlock;
VecAdd<<<blocks, threadsPerBlock>>>(d_A, d_B, d_C);

如果 N=2050 且每块 1024 线程，就需要 3 个 Block；多出的 1022 个线程由边界检查跳过。Block 大小应结合硬件资源和性能测试选择，而不是越大越好。

关键区别：Block 是逻辑调度单位，SM 是物理计算硬件，Warp 是线程执行分组。Triton Program Instance 大致对应 CUDA Block，但 Triton 采用更高层的 Tile 操作抽象。
